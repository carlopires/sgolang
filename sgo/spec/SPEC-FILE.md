Ambient file-system access stays denied (SGO-FILE-001). Spec 0.5.0 admits confined directory grants and owned file handles (SGO-FILE-002, SGO-FILE-003; D52-D56, D59), with in-memory fakes in lab runs (D58).

### SGO-FILE-002 — Directory grants and confined paths (subset 3)
- **version:** 3
- **status:** frozen
- **reference_closure:** SGO-FILE-001, SGO-FILE-003, SGO-AUTH-002, SGO-TYPE-005, SGO-CAP-001, SGO-DEF-003, SGO-CANCEL-002, SGO-BUILD-001, SGO-LAB-002; D52, D53, D55, D56, D58, D59 (amended: `List`).
- **grammar_and_types:** In the main module's `sgo.mod`: `grant dir NAME PATH ro|rw`, where NAME is a lower-case letter followed by at most 31 of `[a-z0-9_-]` and PATH is absolute or relative to the working directory when the program starts; each NAME at most once. API: `root.Dir(name string) *sgo.Dir`; on `d *sgo.Dir`: `Open(path string) (*sgo.File, error)`, `Create(path string) (*sgo.File, error)`, `ReadFile(path string) (string, error)`, `WriteFile(path, data string) error`, `Remove(path string) error`, `Mkdir(path string) error`, `List(path string) (*sgo.Listing, error)`, `Sub(path string) (*sgo.Dir, error)`, `ReadOnly() *sgo.Dir`, `LendTo(n *sgo.Nursery) *sgo.Dir`; on `l *sgo.Listing`: `Len() int`, `Name(i int) string`. `*sgo.Dir` and `*sgo.Listing` are capability handle types (SGO-TYPE-005). A path is a sequence of names separated by `/`: no empty name, `.`, `..`, NUL, or leading `/`; names of at most 255 bytes; at most 4096 bytes in total. `List("")` names the handle's own directory; `""` is not a path for any other operation. No seek, rename, link, permission, or metadata operation is admitted.
- **preconditions:** `root.Dir` is called by the root task (children use a lent handle) with a declared NAME. `Create`, `WriteFile`, `Remove`, and `Mkdir` need a handle that is neither from an `ro` grant nor `ReadOnly`.
- **evaluation_and_value_semantics:** When the program starts, each granted directory is opened once and held; later renames of PATH do not move the grant. A path is resolved from the held directory, never as a string and never from the working directory, and no symlink is followed: a symlink anywhere in the path is `PathRejected`. On linux 5.6 and later the kernel resolves it (`openat2` with `RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS | RESOLVE_NO_MAGICLINKS`), which guarantees that the object opened is inside the held directory even while other processes rename; whether `openat2` is available is decided once per process. Elsewhere (darwin, older linux, or a seccomp filter that denies `openat2`) the path is resolved one name at a time, and after the last name is open the chain is verified from the held directory down (each name still names the object opened for it); the resolution starts over at most 4 times, then `PathRejected`. Both resolutions give the same outcome for every path the environment does not change concurrently. `Open` opens a regular file for reading; `Create` creates or truncates a regular file for writing, truncating only after the resolution is verified. Anything else (a FIFO, device, or socket) is opened without blocking, closed again, and refused with `NotRegularFile`, with no effect (W12 R4). `ReadFile` returns a whole file of at most 16 MiB (`TooLarge` beyond). `Remove` removes a file, an empty directory, or a symlink itself. `List` returns the names in the directory, sorted by byte order, without `.` and `..`; `Name(i)` with `i` outside `0 .. Len()-1` fails with `InvalidArgument`. `Sub` returns a handle whose paths are resolved under a subdirectory; `ReadOnly` and `Sub` never widen a handle.
- **ownership_and_lifecycle:** A `*sgo.Dir` is an immutable capability, like the effect handles of SGO-AUTH-003: a lent copy is revoked when its nursery closes. Files it opens follow SGO-FILE-003.
- **effect_and_capability_requirements:** Only declared grants exist; dependencies cannot add one, and no operation reaches a path outside the granted directory (D53). The grants are part of the build identity: the build ID names the digest of their canonical text (`io=`).
- **concurrency_and_memory_order:** Operations of different tasks on the same tree are not ordered by S-Go; the file system orders them. Another process may change the tree concurrently. With kernel resolution, an open either reaches an object inside the granted directory or fails. With the verified walk, the same holds for every object S-Go returns; a `Create` raced by a rename fails with `PathRaced` if it created an empty file where the rename moved the path (the walk creates exclusively, so it knows), and never truncates an existing one (W12 R11). `Mkdir` and `Remove` act on a parent directory that was inside the grant when resolved; if another process moved it out before the effect, the effect has happened outside and the operation fails with `PathRaced` (W12 R6). The S-Go program has no authority over anything outside its grants.
- **allowed_nondeterminism:** The interleaving of operations of different tasks, and the order of a concurrent environment's changes; each resolution outcome is one admitted by the model `sgo/model/iopath.go`.
- **failure_and_partial_progress:** Errors are returned values with a kind: `PathRejected`, `NotFound`, `Exists`, `NotEmpty`, `IsDirectory`, `NotRegularFile`, `ReadOnly`, `TooLarge`, `PathRaced`, `IOError`; `sgo.NoEffect(err)` is true for every kind but `IOError` (effect unknown) and `PathRaced` (an effect happened). In the lab the fake file system holds only directories and regular files, so `NotRegularFile` cannot occur there, and no other process renames. A directory grant that cannot be opened at start is not an error at start: every operation on it returns the open's error. Writes through a read-only handle, an undeclared NAME, `root.Dir` from a child, and use of a revoked handle fail the task with `MissingCapability`.
- **cancellation_and_cleanup:** Directory operations are bounded system calls, not cancellation points while in the kernel: cancellation is observed before each starts (D55).
- **compile_link_checks:** `SGO_E_USAGE` for malformed or duplicate `grant dir` lines; the linker accepts only the driver's canonical grant text (`-sgoiogrants`). `SGO_E_CAPABILITY_MISUSE` for nil or comparison of the handles; `SGO_E_DISCARDED_ERROR` for unused errors; `SGO_E_UNADMITTED` for other members.
- **runtime_guards:** Component-wise resolution with `O_NOFOLLOW` and chain verification; root-task check of `root.Dir`; read-only and revocation checks before any effect.
- **tcb_assumptions:** The host's `openat`, `fstatat`, `mkdirat`, `unlinkat`, and directory reading (getdents64 on linux; libc on darwin) behave as documented; `src/runtime/sgo_fs.go`, `sgo_iodir.go`, `sgo_iogrant.go`, and the system call layers `sgo_io_sys_*`.
- **positive_tests:** I01, I06; fixture:file-confined-paths, fixture:file-dir-ops, fixture:lab-file-dir-ops; TestSGoResolve, TestSGoResolveRenameRace, TestSGoDirList, TestSGoResolutionPathsAgree (both resolutions), TestSGoOpenat2EPERMIsAnOpenError; the model's I01 scenarios (`sgo/model/iopath_test.go`).
- **negative_tests:** S13; fixture:file-readonly-create, fixture:file-undeclared-grant, fixture:file-dir-from-child, fixture:file-grant-bad-mode, fixture:file-open, fixture:file-open-fifo; TestSGoRenameRaces (PathRaced, Create never truncates through a raced path), TestSGoCreateRaceReported (a raced walk-mode Create that created a file reports PathRaced).
- **implementation_coverage:** W09: model `sgo/model/iopath.go`; runtime `src/runtime/sgo_fs.go`, `sgo_iodir.go`, `sgo_iogrant.go`, `sgo_iofake.go`; API `src/sgo/io.go`; driver `src/cmd/sgo/iogrant.go`; linker `-sgoiogrants`; admission lists.
- **executed_evidence:** `sgo/evidence/w09/README.md` (model path and handle scenarios; runtime tests; the conformance cases above on darwin/arm64, linux/amd64, linux/arm64).
- **supported_execution_configurations:** production; lab (an in-memory tree per grant, empty at the start of the run, with the same contracts and errors; every operation is a choice point; no host file is reached, D58).

### SGO-FILE-003 — I/O handles: ownership, progress, and closing (subset 3)
- **version:** 1
- **status:** frozen
- **reference_closure:** SGO-FILE-002, SGO-NET-002, SGO-SYNC-002, SGO-PERMIT-002, SGO-CANCEL-002, SGO-DEF-003, SGO-TYPE-005; D54, D55, D56.
- **grammar_and_types:** `*sgo.File` with `Read(max int) (string, error)`, `Write(s string) (int, error)`, `Size() (int, error)`, `Close() error`, `LendTo(n *sgo.Nursery) *sgo.File`; the same contract applies to `*sgo.Conn` and `*sgo.Listener` (SGO-NET-002). `sgo.Progress(err error) int`, `sgo.NoEffect(err error) bool`, `sgo.IsEOF(err error) bool`. The handles are capability handle types (SGO-TYPE-005).
- **preconditions:** Only the owner closes a handle. `LendTo(n)` is called by the owner, and `n` is a nursery the owner owns.
- **evaluation_and_value_semantics:** `Read(max)` returns at least 1 and at most `max` bytes, or an error with progress 0 (end of file: `sgo.IsEOF`); `max == 0` returns `""` and nil. `Write(s)` writes all of `s`, or returns an error and the bytes written (`sgo.Progress(err)`). File system calls are bounded to 1 MiB each.
- **ownership_and_lifecycle:** A handle is owned by the task that opened, dialed, or accepted it. While lent to a nursery that has not closed, tasks running inside it may use the handle, and `Close` fails with `HandleLent` and no effect. Any other task's use fails with `MissingCapability`. Every open makes a new handle; after `Close` it refers to nothing, and every operation on it is `HandleClosed`, even if the host reuses the descriptor. A handle not closed by its owner is closed at the exit of the nursery body it was opened in (before the join) unless it is lent to a nursery still open, and at the end of the owner's task in any case, before the task's outcome is published, each with a `HandleAbandoned` entry in the task's failure sequence.
- **effect_and_capability_requirements:** The handle itself; no ambient authority.
- **concurrency_and_memory_order:** Operations through one handle by different tasks (lent) are serialized by the host per call; S-Go adds no ordering between them. `Close` happens after every operation on the handle (it fails with `HandleLent` while one may still run).
- **allowed_nondeterminism:** Short reads; the split of a write into system calls; which of several lent tasks' operations runs first. Each history is one admitted by the model `sgo/model/iohandle.go`.
- **failure_and_partial_progress:** Every I/O error carries its progress; `sgo.NoEffect(err)` is true only when nothing was transferred and the operation may be retried safely (false for `IOError`, whose effect is unknown). A cancellation after partial progress returns both the bytes and the cancellation error (`sgo.IsCancelled`). Closing by a non-owner, and lending to a nursery the owner does not own, are `SpawnContractViolation`.
- **cancellation_and_cleanup:** Socket waits are cancellation points (SGO-NET-002). A file system call is not interruptible: cancellation is observed before it starts and between the bounded calls of one `Write`, never inside one; nothing reports a running call as stopped (D55). No handle outlives its owner task.
- **compile_link_checks:** `SGO_E_CAPABILITY_MISUSE` for nil or comparison; `SGO_E_DISCARDED_ERROR` for unused errors (including `Close`); `SGO_E_UNADMITTED` for other members.
- **runtime_guards:** Ownership and lend checks before every operation; an in-progress counter for `Close`; abandonment resolution with tokens and permits.
- **tcb_assumptions:** `src/runtime/sgo_io.go` and the obligation resolution of TCB-P12.
- **positive_tests:** I03, I04, I05; fixture:file-handle-lent, fixture:file-handle-closed, fixture:file-dir-ops, fixture:net-cancel-progress; TestSGoHandle, TestSGoNet; the model's handle scenarios (`sgo/model/iohandle_test.go`).
- **negative_tests:** I04, I05; fixture:file-handle-lent, fixture:file-handle-closed; the model's seeded bug (closing a lent handle); TestSGoHandle (foreign close, lend outside the owner's nurseries).
- **implementation_coverage:** W09: model `sgo/model/iohandle.go`; runtime `src/runtime/sgo_io.go`, `sgo_ioapi.go`; API `src/sgo/io.go`.
- **executed_evidence:** `sgo/evidence/w09/README.md` (model path and handle scenarios; runtime tests; the conformance cases above on darwin/arm64, linux/amd64, linux/arm64).
- **supported_execution_configurations:** production; lab (fake handles with the same contract, D58).
