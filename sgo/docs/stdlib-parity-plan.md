# Standard-library parity — roadmap (draft for decisions D134–D142)

Status: **draft, awaiting owner approval.** Nothing here is admitted or implemented. Each work
package below gets its own clause drafts (D110) for approval before implementation, and each
freezes at its own spec version, as W14–W17 did.

## 1. Where S-Go stands (spec 0.14.1)

S-Go has 7 `std` packages with 96 exported declarations: `errors`, `strings`, `bytes`, `strconv`,
`utf8`, `sort`, `math`. Go has about 150 packages. Where an S-Go function has a Go counterpart, it
gives Go's results: `test-std-diff` runs both on generated inputs on every CI build, with 9,784
identical checks. Package `sgo` covers `os`/`net`, `time`, `rand`, `sync`, goroutines, `context`,
and `testing`, but as capabilities passed from `main`, with a different API.

The rest is missing because of language rules, not effort:

| Missing | Blocked by | Clause |
|---|---|---|
| `fmt`, `encoding/json`, `text/template`, `errors.As` | reflection; variadic parameters; generics | SGO-REFLECT-001, SGO-TYPE-003, SGO-GEN-001 |
| `slices`, `maps`, `container/*`, `cmp` | generics | SGO-GEN-001 |
| float `math`, float `strconv`, `%f`, JSON numbers | floating point | SGO-FLOAT-001 |
| `io`, `bufio`, `strings.Reader`, `bytes.Buffer` | nothing any more (interfaces arrived in 0.14.0) | — |
| `unicode` tables, `regexp`, `crypto/*`, `compress/*`, `hash/*` | package-level tables (no package variables, D109) | SGO-BIND-* |
| `net/http`, `encoding/*` built on readers | `io` | — |

**Not a goal:** `unsafe`, `cgo`, `syscall`, `plugin`, `reflect` itself, `os/exec`, ambient
`os.Getenv`/`os.Open`, `runtime` internals. S-Go excludes them by construction (constitution,
SGO-NATIVE, SGO-CAP). The target is the commonly used, safe subset of the library, with Go's
behavior wherever S-Go has the feature. Code using the excluded parts will always need changes.

## 2. Proposed work packages, in order

Ordered by how much ordinary Go code each one unblocks per unit of risk.

| WP | Content | Needs | Size / risk |
|---|---|---|---|
| **W18** | `std/io` (`Reader`, `Writer`, `ReadAll`, `Copy`, `EOF`), `std/bufio` (`Scanner`, `Reader`, `Writer`), `strings.Reader`, `bytes.Buffer`; `sgo.File`/`sgo.Conn` adapters with Go-shaped `Read(p []byte)` | interfaces (done); D134, D135 | medium / low |
| **W19** | Package-level frozen tables (D136); then `std/unicode` (categories, `ToUpper`/`ToLower` beyond ASCII), `std/hash/crc32`, `std/crypto/sha256`, `std/encoding/hex`, `std/encoding/base64` | D136 (a language change) | medium / medium |
| **W20** | Variadic parameters (D137); `std/fmt` without reflection (D138): `Sprint`, `Sprintf`, `Fprintf` to an `io.Writer`, `Errorf` with `%w` | W18; D137, D138 | large / medium |
| **W21** | Generics (D139): type parameters with constraint interfaces, under the sharing rule; then `std/slices`, `std/maps`, `std/cmp`, `container/list`, `container/heap`, `errors.As` | D139; model first | large / high |
| **W22** | Floating point (D140): `float64` with IEEE 754 semantics and checked conversions; float `math`, `strconv.ParseFloat`/`FormatFloat`, `%f`/`%g` | D140 | large / medium |
| **W23** | `std/encoding/json` without reflection (D141): marshalers generated by `sgo generate` from type declarations | W20, W21, W22; D141 | large / medium |
| later | `regexp` (after W19), `net/http` on `sgo.Conn` (after W18/W20), `time` formatting, `text/template` (needs reflection or generation) | — | each its own draft |

After W18–W23, the library would cover what most command-line tools, services, and data
processors import (`fmt`, `io`, `bufio`, `strings`, `bytes`, `strconv`, `errors`, `sort`, `slices`,
`maps`, `math`, `unicode`, `encoding/json`, `encoding/hex`/`base64`, `crypto/sha256`). Porting would
still require S-Go's structured concurrency and capabilities instead of goroutines and ambient I/O.

## 3. Decisions for the owner (D134–D142)

| ID | Question | Recommendation |
|---|---|---|
| D134 | Shape of `std/io` | Go's: `Read(p []byte) (n int, err error)`, `Write(p []byte) (n int, err error)`, `io.EOF` as an `error` value. Readers and writers are task-local interfaces (D132). `sgo.File` and `sgo.Conn` keep their current methods and gain Go-shaped `ReadBytes`/`WriteBytes` methods that `io.Reader`/`io.Writer` adapters wrap. Go code using `io` then ports with only the handle acquisition changed. |
| D135 | Capability handles inside interfaces | Today a handle converts to a user interface, and an interface holding a handle can be `sgo.Copy`'d to another task. The runtime then refuses the operation, since every handle operation checks the owning task (`sgoHandleUser`), so this is sound but fails late. Recommendation: make it a compile-time refusal. `sgo.Copy` of an interface whose dynamic type may be a handle reports `SGO_E_CAPABILITY_MISUSE`; handles cross tasks only by `LendTo`. Interfaces holding handles stay usable within a task (the adapters of D134 need that). |
| D136 | Package-level tables | Admit package-level `var` declarations whose type is `sgo.Frozen[T]` and whose initializer is a constant composite literal: immutable, shareable, initialized before `main`, with no initialization order beyond the declaration order of one package. This unblocks `unicode`, `crc32`, `sha256`, `base64`, and later `regexp`, without admitting mutable package state (D109 stands for everything else). |
| D137 | Variadic parameters | Admit `func f(xs ...T)` and `f(a, b)`, `f(s...)`; `xs` is a slice owned by the callee's task (`T` task-local or not, as today). This is needed for `fmt`, `append`-style helpers, and `errors.Join`. |
| D138 | `fmt` without reflection | `std/fmt` formats `int`, `byte`, `rune`, `bool`, `string`, `error`, `[]byte`, nil, and any value with a `String() string` method (`fmt.Stringer`); with D140 also floats. Other structs, maps, and slices print with `%v` through generated `String` methods (`sgo generate`), not reflection; an operand that cannot be formatted is a compile-time error where the format string is constant, and `%!v(unsupported)` otherwise. Verbs, flags, and widths follow Go's, checked by `test-std-diff`. |
| D139 | Generics | Type parameters on functions and types, with constraint interfaces (`any`, `comparable`, method sets, and the type-set unions of SGO-IFACE-001, admitted only as constraints). Under the sharing rule a type parameter is task-local unless its constraint makes it shareable (D132's rule, by instantiation). Model first, as W13 and W17: the share model gains a generic kind before the compiler work. Implementation is Go's (GC shape stenciling). |
| D140 | Floating point | Admit `float64` (not `float32` or complex): IEEE 754 binary64 with Go's rounding; `NaN` and the infinities are values; conversion from float to int is checked (`Overflow` for out-of-range or `NaN`, never Go's implementation-defined result); `==` on floats is admitted, and map keys of float type are denied (NaN keys). Spec text states the deterministic behavior on amd64 and arm64 (FMA contraction disabled in S-Go code). |
| D141 | `encoding/json` | No reflection: `sgo generate json` writes `MarshalJSON`/`UnmarshalJSON` methods from type declarations and field tags given as comments (struct tags stay denied), and `std/encoding/json` drives them through interfaces. Output and errors match Go's for the generated types. |
| D142 | Order and scope | W18 → W19 → W20 → W21 → W22 → W23, each with its own drafts, freeze, reviewer verification, and Linux evidence, as W14–W17. W18 and W19 can start now; W21 is the riskiest and is model first. |
